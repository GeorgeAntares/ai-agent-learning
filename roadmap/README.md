# 学习路线

顺序按 2026 年资料比较多、也方便对照的路径来排：先理解代理在做什么，再自己走通一轮，然后才用现成框架。做到某一阶段时，如果那个框架已经不合适，可以换，完成标准不变。

当前进度：路线已写下，实验都还没开始。

## 1. 概念

先分清一个代理和「问一句、答一句」的差别。这一阶段不写代码，也不绑定某一个框架。

要能讲清这五件事各自解决什么问题：

- **循环**：模型可以多走几步，而不是只生成一次回答。
- **工具**：模型可以要求去读文件、查资料或调用一个函数，再根据结果继续。
- **记忆**：这一轮之外，还有什么信息会被留下来。
- **规划**：面对多步任务时，先拆开再做，还是边做边改。
- **人在回路中**：哪一步要停下来等人确认。

完成标准：`journal/` 里有一篇笔记，用自己的话写清上面五件事。不要求代码。

## 2. 最小循环

不用 CrewAI、LangGraph 或其他重框架。用一小段代码走通一次：模型决定调用工具，程序真的执行，再把结果交回模型。

完成标准：

- `labs/` 下有一个实验目录，本机能跑通。
- 该目录的 `README.md` 写了输入是什么、工具做了什么、模型最后回答了什么。
- 密钥只在本机 `.env`，不在代码和笔记里。

## 3. 工具调用

用一个轻量 SDK 接上至少一个真实工具，例如读一个本地文件，或请求一个公开接口。具体用哪一个 SDK，做到这一阶段再选。

完成标准：

- 实验目录里的步骤可以让别人照着复现。
- 如果需要新的环境变量，只把变量名加进根目录的 `.env.example`，不写值。

## 4. 多代理协作

用角色分工完成一件小事。计划使用 CrewAI：每个代理有自己的职责，结果要交接给别人。

完成标准：笔记里写清每个角色负责什么、结果如何交到下一个人、以及一次没做好时是谁的输出出了问题。

## 5. 有状态的长流程

把流程写成可以停、可以续的图。计划使用 LangGraph，至少用到检查点，或一次需要人点头才能继续的暂停。

完成标准：流程中断之后，能从检查点继续，而不是整段重跑。笔记里记下状态存在哪里。

## 6. 评测与追踪

给一个小任务写下「怎样算做对」，并留下代理实际调用了哪些工具的记录。同时养成不把密钥推进仓库的习惯。

完成标准：

- 笔记里有一次评测：做对了什么、做错了什么。
- 能指出这次运行调用了哪些工具。
- `git status` 里看不到 `.env`。
